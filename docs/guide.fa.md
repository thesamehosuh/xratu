## شروع به کار

خراتو رو از [فروشگاه `VS Code`](https://marketplace.visualstudio.com/items?itemName=xratu.xratu) نصب کن، یا آخرین فایل `.vsix` رو از [نسخه ها](https://github.com/thesamehosuh/xratu/releases) بگیر و از مسیر **`Extensions → ⋯ → Install from VSIX…`** نصبش کن.

۱. پوشه پروژه رو توی `VS Code` باز کن و آیکون خراتو رو از نوار کناری بزن.
۲. توی اولین اجرا یکی از سه مسیر راه اندازی رو انتخاب کن:
   - **شروع رایگان** — با یه کلیک `OpenCode 2` رو نصب میکنه و مدل های رایگان رو همزمان بررسی میکنه.
   - **سرویس خودم** — کلید API ابری، اشتراک `ChatGPT`، سرویس های ایرانی یا هر نشانی دلخواه سازگار با `OpenAI` رو وصل میکنه.
   - **مدل محلی** — دنبال `Ollama`، `LM Studio`، `vLLM` یا `llama.cpp` در حال اجرا روی سیستمت میگرده.
۳. یه مدل انتخاب کن و **شروع گفتگو** رو بزن.

صفحه شروع فقط تا وقتی اولین راه اندازی کامل بشه نشون داده میشه (راه اندازی نیمه تمام دفعه بعد ادامه پیدا میکنه). بعد از اون اتصال ها رو توی **تنظیمات ← ارائه دهنده ها** مدیریت کن و موتور اجرا رو از **تنظیمات ← موتورهای اجرا** (یا فرمان **خراتو: راه اندازی Xratu**) عوض کن.

### گفتگوهای ذخیره شده و پوشه پروژه

- **وابستگی به پوشه پروژه**: هر گفتگوی ذخیره شده پوشه اصلی خودش رو یادش میمونه. تاریخچه پروژه های دیگه رو همیشه میتونی بخونی، ولی اجرای ابزارها و بازیابی نقطه بازگشت تا وقتی پوشه اصلی رو باز نکنی (یا اینجا گفتگوی تازه نسازی) قفل میمونه.
- **ارجاع اتصال**: گفتگوهای تازه یه شناسه غیرمحرمانه از اتصالشون ذخیره میکنن. اگه اون اتصال تغییر کرده یا حذف شده باشه، متن گفتگو قابل خوندنه؛ فقط قبل از ادامه دادن توی **ارائه دهنده ها** یه اتصال انتخاب کن.

## فضای کار و پنل ها

خراتو یه فضای کار یکپارچه با یه کادر پیام مشترک و هشت پنل قابل جابجایی داره:

| پنل | کاربرد |
|-----|--------|
| **گفتگو** | چت با ایجنت، تایید درخواست ابزارها، جواب دادن به کارت های تصمیم و هدایت ایجنت وسط کار. |
| **تغییرات** | دیدن تفاوت فایل ها از نقطه بازیابی، علامت زدن فایل های بررسی شده، گذاشتن یادداشت روی فایل ها و باز کردن نمای تفاوت کامل `VS Code`. |
| **فعالیت** | نمای فقط خواندنی از خروجی کامل ابزارها، دستورها و زمان اجرا، در حالی که مراحل تمام شده توی گفتگو جمع میشن. |
| **ایجنت ها** | دنبال کردن زیرعامل های داخلی یا `OpenCode`، دیدن روند زنده کار، فرستادن دستور بعدی، تایید کارها و توقف جداگانه هر زیرعامل. |
| **پس زمینه** | دیدن خروجی زنده دستورهای طولانی ترمینال و متوقف کردنشون هر وقت لازم شد. |
| **دانلود ها** | پیگیری دانلودهای قابل ادامه همین گفتگو با دکمه های ادامه، تلاش دوباره و لغو. |
| **مرورگر** | صفحه کرومیوم مشترک با ایجنت برای بررسی صفحه، گرفتن اسکرین شات و کلیک و تایپ زنده. |
| **درخواست ادغام** | پیگیری PR های متصل گیت هاب، وضعیت تست ها، نظر بررسی کننده ها و دیدگاه ها. |

### چیدمان و جابجایی پنل ها

- **گفتگو** همیشه توی بخش اصلی میمونه. پنل های **تغییرات**، **فعالیت**، **ایجنت ها**، **پس زمینه**، **دانلود ها**، **مرورگر** و **درخواست ادغام** رو میتونی بین تب های اصلی و پنل کناری بکشی یا از منوی هر تب جابجا کنی.
- توی پنل های پهن، **تغییرات** به شکل پیش فرض کنار **گفتگو** باز میشه. توی عرض باریک نوار کناری، همه نماها توی ردیف تب های اصلی قرار میگیرن.
- برای تغییر عرض پنل کناری، خط جداکننده رو بکش یا با کلیدهای جهت تنظیمش کن. چیدمان و عرض ذخیره میشن و بستن یه تب هیچ وقت کار در حال اجرا رو متوقف نمیکنه.

### کادر پیام و کنترل های نشست

- **حالت ساخت و برنامه**: توی حالت **ساخت** ایجنت میتونه فایل ها رو ویرایش کنه و دستور اجرا کنه (طبق تنظیم تایید تو). حالت **برنامه** فقط خواندنیه و فهرست کار میسازه؛ ابزارهای تغییردهنده، نوشتن های MCP و واگذاری کار توی کد مسدودن، نه فقط با پرامپت.
- **حالت با تایید و YOLO**: پیش فرض **با تایید** هست؛ ویرایش فایل، دستور ترمینال، کارهای مرورگر و ابزارهای MCP قبل از اجرا توی گفتگو ازت اجازه میگیرن. اگه اجرای بدون وقفه روی ایجنت اصلی و زیرعامل ها میخوای، توی کادر پیام **YOLO** رو روشن کن (انتخابت ذخیره میشه؛ نقطه های بازیابی همچنان گرفته میشن و حالت **برنامه** هنوز تغییرات رو مسدود میکنه).
- **پیوست و هدایت وسط کار**: از کادر پیام عکس، PDF یا فایل کد پیوست کن، با `@` به فایل های پروژه ارجاع بده، یا توی اکسپلورر `VS Code` روی فایل ها راست کلیک کن و **پیوست به گفتگوی خراتو** رو بزن. وسط کار ایجنت هم میتونی پیام هدایت بفرستی.
- **نشست های طولانی**: فشرده سازی خودکار زمینه، کارهای طولانی رو زنده نگه میداره و نوار پایین کادر پیام شاخه گیت فعال و شاخص پر شدن زمینه رو نشون میده. روی موتور داخلی میتونی پیام های قبلی رو ویرایش و دوباره ارسال کنی.
- **پیش نویس پیام ها**: متن ارسال نشده همراه گفتگو و پوشه پروژه توی جابجایی بین صفحه ها، گفتگوها و بارگذاری دوباره حفظ میشه. فایل های پیوست فقط توی حافظه میمونن و بعد از بارگذاری دوباره باید دوباره اضافه بشن.

### نوار کناری تنظیمات

با باز کردن تنظیمات از نوار بالا به سه گروه دسترسی داری:

- **مدل ها و موتورها**: **ارائه دهنده ها**، **موتورهای اجرا**
- **منابع ایجنت**: **سرور ها** (MCP)، **فروشگاه**، **مهارت ها**، **فایل های ایجنت**
- **ترجیحات**: **مصرف**، **پروکسی**، **ظاهر**، **تنظیمات**

توی **تنظیمات** میتونی **زبان** رابط (فارسی / انگلیسی)، **زبان پاسخ** (خودکار / فارسی / انگلیسی)، سطح جزئیات گفتگو، نمایش فکر کردن و دستورها، **حالت آفلاین**، **توضیح خطا ها** (توضیح فارسی خطاهای شناخته شده سرویس دهنده بدون درخواست اضافه به مدل) و **پاک کردن تاریخچه** رو تنظیم کنی.

توی **ظاهر** میتونی پیروی از تم `VS Code` یا تم تیره رو انتخاب کنی، رنگ تاکیدی آماده یا دلخواه بذاری، اشباع و کنتراست رو تنظیم کنی، اندازه فونت رابط، متن و کد رو عوض کنی و عرض، تراکم و کاهش حرکت رو انتخاب کنی.

صفحه های **ارائه دهنده ها**، **سرور ها**، **مهارت ها** و **فایل های ایجنت** مشخص میکنن برای کدوم موتور هستن. دیدن تنظیمات موتور دیگه هیچ وقت موتور گفتگوی فعلی رو عوض نمیکنه.

### ورود با اشتراک ChatGPT

توی **تنظیمات ← ارائه دهنده ها**، گزینه **افزودن اتصال ← ادامه با ChatGPT** رو بزن و دسترسی رو توی مرورگر تایید کن. اگه مرورگر نتونست به `VS Code` برگرده، بخش **مرورگر وصل نشد؟** رو باز کن و کل نشانی بازگشتی رو وارد کن. توکن ها توی `SecretStorage` خود `VS Code` ذخیره میشن و مصرف اشتراک توی صفحه **مصرف** جدا از هزینه کلید API نشون داده میشه. برای شرایط حساب و جزئیات بیشتر [مستندات ورود OpenAI](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) رو ببین.

### رانتایم های محلی و حالت آفلاین

`Ollama`، `LM Studio`، `vLLM` یا `llama.cpp` رو اجرا کن و توی **تنظیمات ← ارائه دهنده ها** اسکنش کن.

- برای `Ollama` روی `localhost:11434`، بخش **مدیریت مدل های Ollama** رو باز کن تا مدل ها رو مستقیم از توی خراتو دانلود یا حذف کنی. مدل های بقیه رانتایم ها توی برنامه خودشون مدیریت میشن.
- توی **تنظیمات**، **حالت آفلاین** رو روشن کن تا ترافیک شبکه خراتو فقط به نشانی های همین سیستم (`localhost`، `127.0.0.1`، `::1`) محدود بشه و سرویس های ابری، `OpenCode`، پژوهش وب و MCP خارجی غیرفعال بشن. دستورهای ترمینال همچنان محدود نمیشن.

برای راهنمای قدم به قدم و حساب و کتاب واقعی RAM و VRAM، [راهنمای حالت آفلاین و مدل محلی](../assets/guides/offline.fa.md) رو ببین.

### برای توسعه دهنده های ایران

- **درگاه های ایرانی به عنوان پریست اصلی**: `Kaya AI`، `Avalai`، `GapGPT`، `Metis AI`، `Liara AI`، `ArvanCloud AI` و `Navaan` توی **تنظیمات ← ارائه دهنده ها** گروه خودشون رو دارن، پرداخت ریالی میگیرن و به VPN نیاز ندارن.
- **محاسبه هزینه به تومان**: نرخ هر میزبان (`xratu.providerPricing`) یا نرخ پشتیبان دلار (`xratu.tomanPerUsd`) رو تنظیم کن تا هزینه ها توی صفحه **مصرف** به تومان نشون داده بشن.
- **مقایسه سرعت اتصال ها**: توی **ارائه دهنده ها** بخش **مقایسه سرعت اتصال ها** رو باز کن تا یه پیام کوتاه و اختیاری `Reply with OK.` (با سقف ۳۲ token و بدون محتوای پروژه) به مدل فعال بفرسته و زمان اولین token متنی، زمان کل و هزینه تخمینی رو مقایسه کنی.
- **سازگار با پروکسی**: با حالت **System Proxy** کلاینت های Clash و v2rayN مستقیم کار میکنه؛ نیازی به TUN نیست.
- **فارسی اول**: رابط کامل راست به چپ، تاریخ جلالی، توضیح فارسی خطاها و پاسخ های فارسی طبیعی با مهارت از پیش بارگذاری شده `natural-farsi`.

## موتورهای اجرا

خراتو دو موتور اجرا رو توی یه فضای کار مشترک پشتیبانی میکنه. تغییر موتور یه گفتگوی تازه باز میکنه و تاریخچه قبلی دست نخورده میمونه؛ با باز کردن هر گفتگوی ذخیره شده، همون موتور اصلیش ادامه پیدا میکنه.

| قابلیت | موتور داخلی خراتو | `OpenCode 2` |
|--------|-------------------|--------------|
| **مدل ها و ورود** | کلیدهای ابری، سرویس های ایرانی، اشتراک `ChatGPT`، مدل های محلی | مدل های رایگان `OpenCode` + سرویس های تنظیم شده داخل خود `OpenCode` |
| **ابزارهای مشترک خراتو** | فایل، ترمینال، وب، فایل فشرده، دانلود، PR، مرورگر، MCP و مهارت ها | از سرورهای MCP، مهارت های فعال، مرورگر، دانلودها، PR ها، پژوهش وب و فهرست کارهای خراتو استفاده میکنه؛ ابزار فایل و ترمینال بومی خودش رو نگه میداره |
| **تایید و حالت برنامه** | با تایید / YOLO؛ حالت برنامه تغییرات رو توی کد مسدود میکنه | با تایید / YOLO با کارت های خراتو؛ حالت برنامه تغییرات و واگذاری رو مسدود میکنه |
| **زیرعامل ها** | پروفایل های داخلی و سفارشی `.md` با تاریخچه ماندگار | ایجنت های بومی `OpenCode` با روند زنده، تایید مشخص و دکمه توقف |
| **نقطه بازیابی و برگشت** | نقطه های بازیابی جدا + ویرایش و ارسال دوباره پیام و برگشت گفتگو | نقطه های بازیابی جدا (فقط فایل ها)؛ برگشت تاریخچه بومی گفتگو نداره |
| **حالت آفلاین** | پشتیبانی میشه (رانتایم های محلی) | در دسترس نیست (خراتو نمیتونه شبکه پروسه `OpenCode` رو محدود کنه) |

### نصب و مدیریت OpenCode 2

به **تنظیمات ← موتورهای اجرا ← OpenCode 2** برو. اگه نسخه `2.x` روی `PATH` سیستمت باشه خراتو پیداش میکنه؛ وگرنه با یه کلیک فایل مستقل و بررسی شده نسخه `2.0.30` رو توی فضای ذخیره `VS Code` نصب میکنه، بدون نیاز به Node.js یا npm.

- روی ویندوز، مک و لینوکس (x64/arm64، نسخه های baseline x64 و Linux musl) کار میکنه و نمایش پیشرفت، لغو، تلاش دوباره و مسیر اجرایی دلخواه داره.
- توی نصب مدیریت شده، وقتی نسخه جدید تایید شده بیاد دکمه **بروزرسانی موتور** فعال میشه و با **حذف موتور** رانتایم متوقف میشه و گفتگو به خراتو برمیگرده (فایل های لازم برای گفتگوهای ذخیره شده و کلیدها، تنظیمات و تاریخچه `OpenCode` حفظ میشن).
- نسخه `1.x` شناسایی میشه ولی پشتیبانی نمیشه. قبل از مهاجرت از `1.x` از تنظیمات و تاریخچه `OpenCode` پشتیبان بگیر.

### مدل های رایگان و بررسی در دسترس بودن

انتخابگر مدل `OpenCode` اسم ارائه دهنده رو کنار هر مدل نشون میده و پیش فرض روی **فقط مدل های رایگان** هست (برای دیدن مدل های پولی تنظیم شده توی `OpenCode` فیلتر رو خاموش کن). با باز کردن انتخابگر، همه مدل های رایگان همزمان با یه تست کوتاه و جدا بررسی میشن و وضعیت یا محدودیت درخواستشون همراه زمان تست نشون داده میشه؛ دکمه کنار هر مدل هم برای تست دوباره هست. اگه مدل رایگان قبلی از فهرست حذف بشه، خراتو یه مدل رایگان تایید شده دیگه انتخاب میکنه و هیچ وقت خودکار سراغ مدل پولی نمیره.

### نحوه کار OpenCode داخل خراتو

- **ورود و نشست های جدا**: `OpenCode` از کلیدها و تنظیمات CLI خودش استفاده میکنه و خراتو کلیدهای خودش رو به اون کپی نمیکنه. توی **ارائه دهنده ها** (روی دامنه `OpenCode`) ورود ساده با کلید API و OAuth مستقیم انجام میشه؛ روش هایی که فرم اضافه یا دستور میخوان هنوز از CLI خود `OpenCode` انجام میشن.
- **امکانات مشترک خراتو**: سرورهای MCP فعال خراتو از یه اتصال محلی احراز هویت شده در اختیار `OpenCode` قرار میگیرن (با حفظ پروکسی، زمان انتظار و تایید خودکار خراتو؛ توی حالت برنامه مسدودن). مهارت های فعال خراتو هم از طریق ابزار مشترک مهارت در دسترسن، در حالی که فهرست MCP، مهارت و ایجنت های بومی `OpenCode` فقط خواندنی میمونن.
- **تایید، هدایت و ایمنی**: درخواست دسترسی با کارت تایید خراتو و سوال ها با کارت تصمیم نشون داده میشن و خروجی ترمینال زنده توی **پس زمینه** میاد. پیام های هدایت وسط کار توی مرز مرحله بعدی تحویل داده میشن و فایل های پیوست و ارجاع های `@` با محتوای کامل به صورت اسنپ شات محلی فرستاده میشن. بعد از سه ویرایش ناموفق پشت سر هم با ابزار فایل بومی، اجرا خودکار متوقف میشه (حتی توی YOLO) تا خطا رو بررسی کنی یا مدل رو عوض کنی؛ تغییرات قبلی برگردونده نمیشن.

## نقطه های بازیابی و بررسی تغییرات

قبل از هر ارسال و ویرایش، خراتو یه اسنپ شات از پوشه کاری توی یه مخزن **shadow git** جداگانه توی فضای ذخیره افزونه میگیره. مخزن `.git` واقعی پروژه، مرحله بندی و تاریخچه commit های تو هیچ وقت دستکاری نمیشن.

- **بررسی خط به خط**: پنل **تغییرات** (یا دکمه **بررسی تغییرات** روی هر نوبت) رو باز کن تا تفاوت هر فایل رو ببینی، فایل ها رو **بررسی شده** علامت بزنی، یادداشت به پیش نویس کادر پیام اضافه کنی یا تفاوت کامل رو توی ادیتور `VS Code` باز کنی.
- **بازیابی**: از پالت فرمان، **خراتو: بازیابی نقطه بازگشت…** رو اجرا کن. بازیابی روی کل پوشه کاری اعمال میشه و اول یه اسنپ شات امن ذخیره میکنه تا اگه پشیمون شدی برگردی. قبل از بازیابی، پروسه های در حال اجرا توی این پوشه رو از **پس زمینه** متوقف کن. بازیابی فقط فایل ها، تاریخچه گفتگو رو حفظ میکنه.

## زیرعامل ها

> قالب فایل پروفایل و ذخیره سازی محلی زیر برای موتور داخلی خراتو هست. `OpenCode` از تعریف ایجنت های بومی خودش استفاده میکنه که توی خراتو فقط خواندنی نشون داده میشن.

هر زیرعامل یه گفتگوی فرعی با زمینه، وظیفه و در صورت نیاز مدل جداگانه هست. هماهنگ کننده داخلی گفتگوهای فرعی رو روی دیسک نگه میداره تا بعد از باز کردن دوباره پنجره هم بتونی همون گفتگو رو ادامه بدی. پروفایل فقط تنظیمات شروع کاره و ویرایش فایلش، زیرعامل هایی رو که قبلا ساخته شدن عوض نمیکنه.

| پروفایل داخلی | توانایی ها |
|---------------|------------|
| `explore` | خوندن و جستجوی فایل ها و وب؛ بدون ابزار ویرایش یا ترمینال. |
| `verify` | اجرای تست و دستور با تایید واقعی (دستورها ممکنه فایل بیلد بسازن). |
| `general` | بررسی، ویرایش فایل، اجرای دستور و تایید نتیجه ها. |

تنظیم `xratu.maxParallelSubagents` (پیش فرض `4`، بازه `1–8`) تعداد زیرعامل های همزمان رو محدود میکنه و بقیه کارها خودکار توی صف میمونن. زیرعامل های ویرایشگر و ایجنت اصلی با یه قفل نوبتی روی پوشه مشترک هماهنگ میشن، در حالی که زیرعامل های فقط خواندنی `explore` همزمان کنار هم اجرا میشن. این هماهنگی جلوی تداخل ویرایش ها رو میگیره؛ ولی سندباکس ترمینال نیست و `Git worktree` جدا نمیسازه.

### کار با گفتگوهای فرعی

تب **ایجنت ها** رو باز کن تا گفتگوهای فرعی رو ببینی و هدایت کنی (توی نوار کناری باریک، گفتگوی انتخاب شده تمام صفحه باز میشه؛ توی پنل پهن، فهرست کنارش میمونه):

- **هدایت و ادامه**: مستقیم به زیرعامل در حال اجرا پیام بده (توی مرز امن بعدی به مدل میرسه) یا گفتگوی تموم شده اش رو ادامه بده.
- **توقف تکی**: یه زیرعامل رو بدون متوقف کردن بقیه یا ایجنت اصلی متوقف کن.
- **تایید و سوال اختصاصی**: درخواست تایید یا سوال هر زیرعامل رو توی گفتگوی خودش (یا از گفتگوی اصلی؛ هر دو همون یه درخواست رو جواب میدن) تایید کن.
- **تنظیم بین اجراها**: بین دو اجرا، مدل، عمق استدلال یا سقف دورهای هر زیرعامل رو عوض کن.
- **بررسی دستی**: از بخش **فایل های ایجنت** مستقیم یه زیرعامل تازه راه بنداز و هر وقت خواستی نتیجه اش رو برگردونی، **فرستادن نتیجه به گفتگوی اصلی** رو بزن.

اگه `VS Code` وسط کار دوباره بارگذاری بشه، اجراهای داخلی تمیز متوقف میشن و ابزارهای نامطمئن خودکار تکرار نمیشن. تاریخچه ثبت شده و گزارش ها باقی میمونن و بازیابی نقطه بازگشت، زمینه کنار گذاشته شده رو نامعتبر میکنه.

توی **`OpenCode`** هم زیرعامل های بومی با روند زنده، تاییدها و سوال های مشخص، پیام مستقیم حین اجرا و دکمه توقف تکی توی **ایجنت ها** دیده میشن. حالت **برنامه** واگذاری رو روی هر دو موتور مسدود میکنه.

### نوشتن فایل پروفایل سفارشی

از پالت فرمان، **خراتو: فایل های زیرعامل…** رو باز کن تا همه پروفایل های بارگذاری شده (همراه با خطاها و هشدارهاشون) رو ببینی یا یه پروفایل تازه بسازی. هر پروفایل یه فایل مارکداون با frontmatter YAML هست و بدنه فایل، پرامپت سیستم زیرعامل میشه.

ترتیب جستجو (اولین تطابق برنده):

۱. `.xratu/agents/<name>.md`
۲. `.agents/agents/<name>.md` (مشترک با ابزارهای ایجنتی دیگه)
۳. `.claude/agents/<name>.md` (`Claude Code`)
۴. `~/.agents/agents/<name>.md`
۵. `~/.claude/agents/<name>.md` (`Claude Code`)

```markdown
---
name: code-reviewer
description: کد تغییر کرده رو از نظر درستی و امنیت بررسی میکنه؛ بعد از یه ویرایش بزرگ استفاده میشه.
tools: read_file, grep_search, glob_search, run_terminal_command
model: gpt-5-mini
reasoning_effort: low
max_rounds: 30
---

تفاوت کد رو از نظر مشکلات درستی و امنیت بررسی کن. هر یافته رو با مسیر فایل
و شماره خط بده، از مهم ترینشون شروع کن.
```

| فیلد | معنی |
|------|------|
| `name` | اختیاری؛ باید با اسم فایل یکی باشه (حروف کوچک انگلیسی، عدد و خط تیره تکی). |
| `description` | **اجباری.** به ایجنت اصلی میگه چه موقع کار رو به این پروفایل بسپاره. |
| `tools` | فهرست اختیاری و جدا شده با ویرگول از اسم ابزارهای خراتو. اگه خالی باشه ابزارهای پیش فرض زیرعامل داده میشه. ابزارهای کنترل گفتگوی اصلی، واگذاری، `ask_user_question` و کنترل پروسه مشترک همیشه حذف میشن؛ برای سوال زیرعامل از `ask_session_question` استفاده کن. |
| `model` | شناسه اختیاری مدل این پروفایل (پنجره زمینه و سقف خروجی از همون مدل گرفته میشه). پیش فرض: مدل گفتگوی اصلی. |
| `reasoning_effort` | اختیاری: `none`، `minimal`، `low`، `medium`، `high`، `xhigh` یا `max`. |
| `max_rounds` | سقف اختیاری تعداد دور حلقه این پروفایل (پیش فرض `50`). |

**بررسی ابزارها هنگام بارگذاری**: هر اسمی توی `tools:` موقع بارگذاری با ابزارهای واقعی خراتو چک میشه. اسم های نامعتبر با هشدار حذف میشن و اگه **هیچ** اسم معتبری باقی نمونه، پروفایل خطا میگیره تا زیرعامل بی ابزار و خاموش ساخته نشه (مخصوصا برای فایل هایی که اسم ابزارهاشون مثل `Read`، `Grep` یا `Bash` نوشته شده). خطاها رو توی **خراتو: فایل های زیرعامل…** یا خروجی **Xratu** ببین. زیرعامل های داخلی همچنان برای ویرایش و دستورها تایید واقعی میگیرن.

## مرورگر مشترک

تب **مرورگر** رو باز کن، نشانی سایت یا سرور محلی توسعه رو بزن و مستقیم با صفحه کار کن. میتونی تب **مرورگر** رو به پنل کناری ببری تا کنار **گفتگو** بمونه.

- **کار همزمان با ایجنت**: ایجنت روی همون صفحه ای که میبینی کار میکنه؛ میتونه درخت دسترسی، کنسول و شبکه رو ببینه، اسکرین شات بگیره، آدرس عوض کنه، کلیک و تایپ کنه، اسکرول کنه، اندازه صفحه رو عوض کنه و جاوااسکریپت صفحه رو اجرا کنه.
- **تایید و حالت برنامه**: کارهای تعاملی مرورگر به تایید نیاز دارن، مگر اینکه **YOLO** روشن باشه. توی حالت **برنامه** فقط بررسی فقط خواندنی صفحه ای که از قبل بازه مجازه.
- **فایل اجرایی و ایزوله سازی**: خراتو در صورت نیاز Chrome یا Edge نصب شده رو اجرا میکنه، یا مسیر فایل اجرایی Chromium توی تنظیم `xratu.browserExecutablePath` رو برمیداره. هیچ مرورگری خودکار دانلود نمیشه. مرورگر با سندباکس روشن و پروفایل موقت جدا روی دستگاه میزبان اجرا میشه (توی `VS Code` ریموت، `localhost` به دستگاه ریموت اشاره میکنه).
- **چرخه عمر صفحه**: هر گفتگو یه صفحه مرورگر داره (پنجره بازشو و دانلود مرورگر مسدودن). صفحه با جابجایی تب و بارگذاری دوباره صفحه خراتو حفظ میشه و با عوض کردن گفتگو، بستن مرورگر یا بارگذاری دوباره `VS Code` بسته میشه. **حالت آفلاین** اتصال های باز رو قطع میکنه و فقط نشانی های `loopback` رو مجاز میدونه.

## دانلود ها و فایل های فشرده

خراتو دانلود مدیریت شده HTTP(S)، بررسی صحت فایل و باز کردن امن فایل های فشرده رو مستقیم داخل افزونه داره و هم روی موتور داخلی و هم روی `OpenCode` کار میکنه.

### دانلودهای مدیریت شده

از ایجنت بخواه فایلی رو دانلود کنه (با ابزارهای `start_download`، `control_download` و `list_downloads`) و وضعیتش رو توی تب **دانلود ها** دنبال کن.

- **جدا برای هر گفتگو**: تب **دانلود ها** فقط انتقال های گفتگوی فعلی رو با دکمه های **ادامه**، **تلاش دوباره** و **لغو** نشون میده. لغو کردن فایل ناتمام رو پاک میکنه، ولی فایل های کامل شده روی دیسک میمونن.
- **قابل ادامه و امن**: دانلودهای قطع شده پیشرفتشون رو نگه میدارن و اگه سرور از HTTP `Range` پشتیبانی کنه از ادامه اش میرن. باز کردن پروژه هیچ وقت خودکار دانلود رو از سر نمیگیره؛ بعد از راه اندازی دوباره خودت ادامه رو بزن یا به ایجنت تایید بده. فایل های موجود روی دیسک هیچ وقت رونویسی نمیشن و نشانی منبع (که ممکنه توکن امضا شده داشته باشه) توی `SecretStorage` میمونه، نه توی فایل وضعیت یا رابط کاربری.
- **مسیریابی جدا برای هر دانلود**: هر دانلود میتونه با `auto` (طبق تنظیم پروکسی)، `proxy` یا `direct` انجام بشه، بدون اینکه تنظیم سراسری پروکسی عوض بشه. **حالت آفلاین** دانلودهای فعال رو قطع میکنه و اجازه ادامه نمیده.
- **فایل های بزرگ و نقطه بازیابی**: فایل های دانلود شده ۵۰ مگابایت و بزرگ تر از نقطه های بازیابی جدا میشن تا نوبت های بعدی کدنویسی فایل های چند گیگابایتی رو آرشیو نکنن.

### بررسی صحت فایل و باز کردن فایل فشرده

- **`verify_file`** (فقط خواندنی، کار میکنه در حالت آفلاین): مقدار SHA-256 فایل پروژه رو حساب میکنه و در صورت داشتن مقدار مرجع ناشر، باهاش تطبیق میده.
- **`inspect_archive`** (فقط خواندنی، قابل استفاده در حالت آفلاین و حالت برنامه): فهرست فایل های داخل ZIP، TAR و TAR.GZ/TGZ رو بدون نوشتن روی دیسک نشون میده.
- **`extract_archive`** (با تایید، کار میکنه در حالت آفلاین): فایل های ZIP، TAR و TAR.GZ/TGZ رو بعد از گرفتن نقطه بازیابی توی یه پوشه **تازه** داخل پروژه باز میکنه. هیچ وقت فایل موجود رو رونویسی نمیکنه، `symlink` ها، مسیرهای فرار از پوشه، نام های ناامن ویندوز و ZIP رمزگذاری شده رو رد میکنه، CRC فایل ZIP (و در صورت نیاز SHA-256) رو چک میکنه و هیچ فایل باز شده ای رو اجرا نمیکنه.

## درخواست های ادغام

PR های گیت هاب رو مستقیم توی تب **درخواست ادغام** (یا از پالت فرمان **خراتو: پیگیری درخواست های ادغام…**) دنبال کن.

- **استفاده از ورود محلی `gh`**: خراتو اطلاعات PR رو از طریق [GitHub CLI (`gh`)](https://cli.github.com/) نصب شده روی سیستم با ورود فعلی خودت میخونه. هیچ کلید یا توکن گیت هابی وارد پرامپت یا رابط کاربری نمیشه.
- **وضعیت کامل در یه نگاه**: وضعیت PR (پیش نویس، باز، ادغام شده، بسته)، شاخه مبدا و مقصد، نتیجه بررسی، تست های اجباری و اختیاری CI و نظرهای اخیر رو ببین. از منوی هر ردیف میتونی تازه سازی کنی، توی گیت هاب بازش کنی یا اتصالش رو برداری.
- **حالت پیگیری زنده (Watch)**: با روشن کردن پیگیری (یا خواستن از ایجنت برای زیر نظر گرفتن PR)، خراتو هر ۳۰ ثانیه بدون مصرف توکن مدل وضعیت رو چک میکنه و وقتی تستی رد یا قبول شد، کسی نظر داد یا تداخل ادغام پیش اومد، گفتگوی بیکار رو خودکار بیدار میکنه. پیگیری بعد از باز کردن دوباره `VS Code` حفظ میشه، با بسته شدن یا ادغام PR خودکار متوقف میشه و توی حالت **برنامه** یا **حالت آفلاین** غیرفعاله.

## سرور های MCP

سرورهای Model Context Protocol رو توی **تنظیمات ← سرور ها** یا مستقیم توی دو فایل JSON سازگار با Cline تنظیم کن:

- **سراسری**: `mcp.json` توی پوشه ذخیره سازی سراسری افزونه
- **پروژه**: `.xratu/mcp.json` توی ریشه پروژه (به ازای هر کلید سرور روی تنظیم سراسری اولویت داره و فقط توی پوشه های مورد اعتماد خونده میشه)

از `stdio` (`command`/`args`/`env`)، `websocket` و `streamableHttp`/`sse` (`url`/`headers`) پشتیبانی میکنه. ابزارها با نام `mcp__<server>__<tool>` در دسترس ایجنت قرار میگیرن و مثل ابزارهای داخلی تایید میخوان، مگر اینکه توی صفحه **سرور ها** تایید خودکار اون ابزار رو روشن کنی.

### سرور پیش فرض و سرورهای ایرانی منتخب

- توی نصب تازه، [MCP رسمی مستندات زرین پال](https://www.zarinpal.com/docs/mcpDocs/) (فقط خواندنی، بدون نیاز به کلید API) فعاله. تنظیمات MCP قبلی هیچ وقت رونویسی نمیشن.
- سرورهای ایرانی بالای **فروشگاه** با فیلتر برچسب **ایرانی** قرار میگیرن؛ از جمله اتصال های غیررسمی و فقط خواندنی **[دیجی کالا](https://github.com/sepehr071/digikala-mcp)** (نیازمند `uv`)، **[ترب](https://github.com/mmdju/torob-mcp)** (اجرای محلی با Node.js و Git؛ اجرای اول تا ۲ دقیقه ممکنه طول بکشه) و **[دیوار](https://github.com/mmdju/divar-mcp)** (سرور HTTP آماده). هیچ کدوم قبل از انتخاب خودت وصل نمیشن و کدی اجرا نمیکنن.
- مهارت همراه [`iranian-marketplaces`](../assets/skills/iranian-marketplaces/SKILL.md) به ایجنت کمک میکنه بین دیجی کالا، ترب و دیوار انتخاب درست بکنه و قیمت تومانی و ودیعه اجاره رو دقیق بخونه.

### فروشگاه

توی **تنظیمات ← فروشگاه** سرورها رو بدون نوشتن دستی JSON پیدا و نصب کن:

- **منبع های قابل تنظیم** (`xratu.mcpMarketplaceSources`): پیش فرض کاتالوگ عمومی Cline (با مجوز Apache-2.0) و رجیستری رسمی MCP هست. هر نشانی `http(s)` کار میکنه و لیست خالی کاتالوگ راه دور رو خاموش میکنه.
- **پروکسی محور و قابل استفاده در آفلاین**: کاتالوگ ها سمت افزونه از طریق پروکسی تنظیم شده گرفته میشن، ۲۴ ساعت کش میشن و همیشه با فهرست منتخب داخلی ادغام میشن.
- **نصب شفاف**: هر ردیف دستور یا نشانی دقیق رو نشون میده و قبل از ذخیره، پیکربندی نهایی رو تایید میکنی. سرورهایی که کلید میخوان به فرم ویرایش میرن و تایید خودکار ابزار هیچ وقت از کاتالوگ گرفته نمیشه.
- **تشخیص از README**: اگه سروری توی کاتالوگ اطلاعات نصب نداشته باشه، با درخواست خودت از README مخزن حدس زده میشه و قبل از ذخیره با هشدار نشون داده میشه تا بررسیش کنی.

## مهارت های ایجنت

خراتو از استاندارد باز [agentskills.io](https://agentskills.io) پشتیبانی میکنه تا مهارت ها رو بین خراتو، `Claude Code`، `OpenCode`، `Roo Code` و بقیه ابزارها مشترک نگه داری.

ترتیب جستجو (اولین تطابق برنده):

۱. `.xratu/skills/<name>/SKILL.md`
۲. `.agents/skills/<name>/SKILL.md`
۳. `.claude/skills/<name>/SKILL.md`
۴. `~/.agents/skills/<name>/SKILL.md`
۵. `~/.claude/skills/<name>/SKILL.md`

```markdown

name: deploy-staging
description: Deploy the app to staging; use when the user asks to deploy or ship to staging.
---

1. Run the test suite

3. `npm run deploy:staging`
```

هر مهارت رو میتونی توی **تنظیمات ← مهارت ها** روشن یا خاموش کنی. مهارت های فعال خراتو توی `OpenCode` هم از طریق ابزار مشترک مهارت در دسترسن.

## پروکسی و مسیریابی شبکه

توی **تنظیمات ← پروکسی** مسیر درخواست های خروجی رو کنترل کن:

- **حالت های پروکسی**:
  - `auto` (پیش فرض): به ترتیب `xratu.proxyUrl` ← تنظیم `http.proxy` در `VS Code` ← متغیرهای محیطی (`HTTPS_PROXY`/`HTTP_PROXY`) ← پروکسی سیستم عامل رو چک میکنه.
  - `custom`: فقط از نشانی HTTP/HTTPS مشخص شده و فهرست `noProxy` استفاده میکنه.
  - `off`: مستقیم و بدون پروکسی وصل میشه.
  *(پروکسی SOCKS فعلا پشتیبانی نمیشه.)*
- **اسکن کلاینت محلی**: کلاینت های خانواده Clash (Clash Verge Rev، mihomo، Mihomo Party، Clash Nyanpasu، ClashX)، v2rayN/v2rayA و Surge در حال اجرا روی سیستمت رو پیدا میکنه و به پورت فعالشون قفل میشه. حالت **System Proxy** کافیه و به TUN نیاز نیست.
- **مسیریابی جستجوی وب**: توی صفحه پروکسی (`xratu.webSearchUseProxy`) مشخص کن پژوهش وب از پروکسی رد بشه یا مستقیم بره، جدا از مسیر مدل ها.
- **مسیریابی هر سرور MCP**: هر سرور MCP راه دور رو جدا روی `auto`، `proxy` یا `direct` بذار و قبل از ذخیره با تست اتصال زنده مطمئن شو.

## حریم خصوصی و امنیت

- **کلیدها و اطلاعات محرمانه**: کلیدهای API مدل، توکن های OAuth اشتراک `ChatGPT` و نشانی منبع دانلودهای مدیریت شده توی `SecretStorage` خود `VS Code` ذخیره میشن. مقادیر هدر و متغیر محیطی که توی **تنظیمات ← سرور ها** وارد میکنی به ارجاع امن تبدیل میشن. فایل های `mcp.json` که دستی ویرایش شده باشن ممکنه هنوز مقدار محرمانه داشته باشن؛ هیچ وقت `.xratu/mcp.json` رو توی گیت ثبت نکن. `OpenCode` اطلاعات ورود خودش رو جدا نگه میداره.
- **داده محلی و بدون ردیابی**: تاریخچه گفتگوها و نقطه های بازیابی روی دیسک خودت میمونن. خراتو هیچ تله متری، آنالیتیکس یا گزارش کرشی جمع نمیکنه.
- **پژوهش وب خودکار**: پژوهش وب بدون حساب کاربری یا کلید جستجو خودکار کار میکنه (حتی توی حالت برنامه).
  - ابزار `web_search` پرس و جوی عمومی رو به Parallel Search MCP بدون کلید میفرسته و در صورت خطا یا سهمیه سراغ Exa میره.
  - ابزار `fetch_url` صفحات عمومی رو مستقیم میخونه (مارکداون، کد، لینک و متن PDF با سقف حجم). فقط نشانی های ساده ای که توی نتایج عمومی جستجوی همین گفتگو دیده شده باشن میتونن در صورت نیاز از استخراج Parallel استفاده کنن؛ نشانی های دارای پارامتر یا بخش، فقط مستقیم خونده میشن.
  - سرویس های ابری جستجو متن پرس و جو (یا نشانی عمومی مجاز) و یه شناسه تصادفی گفتگو رو میگیرن. متن پرس و جو بدون تغییر فرستاده میشه، پس مسیر محلی رو توی پرس و جوی `web_search` نذار. هیچ کلید مدل، کوکی یا شناسه نشست بومی فرستاده نمیشه. متن صفحات ۵ دقیقه توی حافظه میمونه و روی دیسک کش نمیشه. `OpenCode` هم از همین لایه پژوهش خراتو استفاده میکنه.
  - تنظیمات قدیمی Brave و SearXNG کنار گذاشته شدن؛ اگه قبلا کلیدی توی تنظیمات `VS Code` ذخیره کردی دستی پاکش کن.
- **مرز حالت آفلاین**: ترافیک شبکه خراتو رو به نشانی های `loopback` محدود میکنه و مدل های ابری، `OpenCode`، پژوهش وب و MCP خارجی رو میبنده. دستورهای ترمینال و لینک هایی که خودت توی مرورگر باز میکنی همچنان محدود نمیشن.
- **گزارش مشکل امنیتی**: آسیب پذیری ها رو به صورت خصوصی از طریق [SECURITY.md](../SECURITY.md) گزارش کن، نه توی تیکت عمومی.
