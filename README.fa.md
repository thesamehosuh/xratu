ایجنت کدنویسی هوش مصنوعی متن باز برای VS Code. کلید خودت یا یه رانتایم
محلی. همه چیز توی extension host و روی سیستم خودت اجرا میشه.

## کلید تو. مدل تو. سیستم تو.

- کلید های API توی مخزن secrets ادیتور VS Code نگه داشته میشن و فقط به
  اندپوینتی که خودت تنظیم کردی میرن.
- کاملا آفلاین کار میکنه: Ollama، LM Studio، vLLM و llama.cpp خودکار
  شناسایی میشن.

## امکانات

- **محیط کار جدید** - گفتگو، تغییرات و فعالیت یه کادر پیام مشترک دارن.
  بعد از پایان پاسخ، ابزار ها توی یه فهرست اختیاری جمع میشن؛ خروجی کامل
  توی فعالیت میمونه. دیف Checkpoint رو همون جا ببین، فایل رو بررسی شده
  علامت بزن و نظرت رو قبل از ارسال به پیش نویس اضافه کن. توی پنل عریض،
  تغییرات کنار گفتگو دیده میشن.
- **صفحه های کناری** - سرویس دهنده ها، سرور های MCP، فروشگاه، مهارت ها،
  فایل های ایجنت، مصرف، پروکسی و تنظیمات با یه کلیک در دسترسن. اتصال جدید
  توی پنل کناری باز میشه و سرویس های ایرانی جلوی چشم میمونن. پیش نویس
  با جابجایی بین صفحه ها حفظ میشه؛ حباب پیام کاربر سمت راست میمونه و
  جهت متن خودش رو تشخیص میده.
- **کدنویسی ایجنتیک** - خوندن فایل، ویرایش کد، اجرای دستور ترمینال و
  جستجوی وب. هر ویرایش و دستور به تایید تو نیاز داره؛ برای گردش کار های
  مورد اعتماد میشه تایید خودکار هر ابزار رو روشن کرد، و حالت YOLO کل
  تایید ها رو برمیداره. **حالت YOLO دروازه تایید رو کلا برمیداره** - ویرایش
  فایل، دستور ترمینال و ابزار های MCP همه بدون پرسش اجرا میشن. Checkpoint
  هنوز قبل از هر ویرایش اسنپ میگیره و حالت Plan هنوز ابزار های ویرایش رو
  مسدود میکنه، ولی هیچی جلوی حلقه رو نمیگیره. بذارش روی یه پوشه موقت، نه
  روی مخزنی که برات مهمه.
- **حالت Plan** - برنامه ریزی فقط خواندنی با فهرست کار. ابزار های ویرایش
  توی کد مسدود میشن، نه با پرامپت.
- **Checkpoint** - اسنپ شات shadow-git قبل از هر ارسال و ویرایش. از دکمه
  **بررسی تغییرات** هر پاسخ یا صفحه **تغییرات**، دیف فایل ها رو ببین و
  دیف کامل رو توی ادیتور باز کن. برای بازیابی، دستور
  **خراتو: بازیابی نقطه بازگشت…** رو توی Command Palette بزن. مخزن git
  واقعیت دستکاری نمیشه.
- **سرور های MCP** - از طریق stdio، WebSocket یا HTTP/SSE، با پیکربندی
  فایل محور سازگار با Cline.
- **مهارت های ایجنت** - استاندارد باز
  [agentskills.io](https://agentskills.io)؛ قابل اشتراک با Claude Code،
  Roo Code، OpenCode و بقیه.
- **زیرعامل ها** - واگذاری یه کار خودبسنده به پروفایل ایجنتی که توی زمینه
  خودش اجرا میشه؛ چند تای همزمان. [زیرعامل ها](#زیرعامل-ها)
- **جلسه های طولانی** - هدایت وسط کار، ویرایش و ارسال مجدد هر پیام، پیوست
  تصویر و PDF، فشرده سازی خودکار زمینه.
- **پروکسی محور** - از تنظیم پروکسی خودت، بعد VS Code، بعد متغیر های محیطی
  یا پروکسی سیستم عامل پیروی میکنه؛ یه اسکن، کلاینت Clash/v2rayN روی
  سیستمت رو پیدا میکنه. مسیریابی هر سرور MCP جدا: خودکار / از طریق پروکسی /
  مستقیم.
- **فارسی اول** - رابط کاربری فارسی، تاریخ های جلالی، توضیح خطاهای فارسی،
  و وقتی بخوای جواب های فارسی محاوره ای.

## برای توسعه دهنده های ایران

- **گیت وی های ایرانی، پریست اول** - Kaya AI، Avalai، Metis AI، Liara AI،
  ArvanCloud AI، Navaan و GapGPT توی Settings → Providers گروه خودشون رو
  دارن، پرداخت ریالی میگیرن و به VPN نیاز ندارن. هزینه مصرف توی صفحه
  Usage با تومان نشون داده میشه.
- **کاملا محلی یعنی کاملا آفلاین** - با یه رانتایم محلی (Ollama، LM Studio،
  vLLM، llama.cpp) ایجنت بدون هیچ وابستگی شبکه کامله.
- **پروکسی بومی** - چیدمان ایرانی معمولا از حالت System Proxy کلاینت های
  Clash/v2rayN رد میشه؛ خراتو همون رو برمیداره (بدون نیاز به TUN)، کلاینت
  محلی و پورت هاش رو اسکن میکنه و ترافیک MCP رو برای هر سرور جدا
  مسیریابی میکنه.
- **فارسی ورودی، فارسی خروجی** - رابط فارسی، تاریخ ها جلالی، توضیح خطاها
  فارسی، و با زبان پاسخ فارسی، ایجنت فارسی محاوره ای مینویسه - مهارت
  `natural-farsi` که همراه محصول میاد، از همون توکن اول بارگذاری میشه و
  لهجه رو نگه میداره.
- **بدون راهنمای دور زدن** - وقتی اندپوینتی در دسترس نیست یا ثبت نامی
  شکست میخوره، ایجنت راه های کارساز رو نشون میده (گیت وی های داخلی، مدل
  های محلی، PaaS ایرانی) نه راهنمای VPN.

### ورود با اشتراک ChatGPT

توی **ارائه دهنده ها**، **افزودن اتصال** و بعد **ادامه با ChatGPT** رو بزن. Xratu از
[روش رسمی ورود برای برنامه های متن باز](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)
استفاده میکنه، برنامه رو برای حساب و فضای کاری خودت ثبت میکنه و قبل از ذخیره
اتصال، امضای توکن هویت رو بررسی میکنه. موقع ورود باید اجازه استفاده از اشتراکت
رو بدی؛ ورود به حساب به تنهایی اجازه ارسال درخواست مدل رو نمیده.

با **کپی لینک** میتونی ورود رو توی مرورگر دلخواهت باز کنی. ورود با مرورگر یه کال بک
روی `127.0.0.1` باز میکنه و اگه پورت اشغال باشه، پورت دیگه ای رو امتحان میکنه.
اگه مرورگرت به میزبان افزونه نمیرسه، مثلا روی SSH یا توی کانتینر، بخش
**مرورگر وصل نشد؟** رو باز کن و **کل آدرس بازگشتی** رو بچسبون. آدرس کامل، اطلاعات لازم
برای بررسی درخواست و ثبت برنامه رو داره. روش رسمی فعلی از ورود با مرورگر استفاده میکنه.

هر حساب و فضای کاری، اطلاعات ورود جداگانه توی SecretStorage خود VS Code داره.
از صفحه اتصال ها حساب اضافه کن یا بین حساب ها جابه جا شو. ورود دوباره از شناسه
ثبت شده همون حساب و شناسه ثابت میزبان استفاده میکنه. خروج، توکن های دسترسی،
تمدید و هویت رو پاک میکنه ولی مشخصات ثبت حساب رو برای ورود بعدی نگه میداره.

فهرست مدل ها و درخواست ها از endpoint عمومی `https://api.openai.com/v1` استفاده
میکنن. درخواست های Responses به صورت جریانی و با `store: false` ارسال میشن.
اسم مدل ها، ترتیب، اندازه کانتکست و گزینه های استدلال از فهرست همون حساب میان.
روش قدیمی Codex دیگه استفاده نمیشه؛ اتصال هایی که با اون روش ساخته شدن باید
دوباره وارد بشن.

صفحه **مصرف** توکن های اشتراک ChatGPT رو که توی ۳۰ روز گذشته در Xratu ثبت شدن،
به تفکیک مدل نشون میده. **مدیریت مصرف** تنظیمات ChatGPT رو برای دیدن سقف مصرف و
اعتبار باز میکنه. مصرف اشتراک از هزینه API جداست و حتی بعد از ویرایش نرخ مدل،
قیمت API براش حساب نمیشه.

توکن پنج دقیقه قبل از انقضا تمدید میشه و بعد از خطای احراز هویت هم دوباره تمدید
میشه. خطای موقت شبکه، توکن معتبر رو پاک نمیکنه؛ رد شدن دائمی نشست، ورود دوباره
لازم داره. توقف چت، انتظار تمدید رو هم قطع میکنه و همه درخواست ها از پروکسی تنظیم
شده استفاده میکنن. خروج، اول لغو نشست روی سرور رو امتحان میکنه و بعد اطلاعات
محلی رو پاک میکنه. اگه لغو نشست تایید نشه، Xratu خبر میده تا اتصال برنامه رو توی
تنظیمات ChatGPT قطع کنی.

## سرور های MCP

پیکربندی از دو فایل خونده میشه:

- **سراسری**: `mcp.json` در global storage افزونه
- **فضای کاری**: `.xratu/mcp.json` در ریشه پروژه (به ازای هر کلید سرور، روی
  پیکربندی سراسری اولویت داره)

قالب پیکربندی با Cline سازگاره: `command`/`args`/`env` برای stdio و
`url` برای سرور های راه دور. ابزار ها با نام `mcp__<server>__<tool>` به ایجنت
معرفی میشن و همون جریان تایید ابزار های داخلی رو دارن.

### فروشگاه

تب **فروشگاه** توی صفحه MCP سرور ها رو از کاتالوگ های زنده میاره. پس به سرور
هایی که دستی وارد میکنی محدود نیستی:

- **منبع ها** قابل تنظیمه (`xratu.mcpMarketplaceSources`). پیش فرض، کاتالوگ
  عمومی منتشرشده توسط پروژه Cline (با مجوز Apache-2.0) و رجیستری رسمی MCP.
  هر آدرس http(s) کار میکنه و لیست خالی یعنی کاتالوگ راه دور خاموش.
- کاتالوگ ها سمت افزونه و **از طریق پروکسی تو** گرفته و ۲۴ ساعت کش میشن.
  همیشه با فهرست منتخب داخلی ادغام میشن، پس فروشگاه آفلاین هم کار میکنه.
- افزودن هیچ وقت بی صدا نیست: هر ردیف فرمان یا آدرس دقیق رو نشون میده و مرحله
  تایید همون پیکربندی رو نشون میده که نوشته میشه. سرور هایی که کلید میخوان
  به فرم ویرایش میرن. تایید خودکار ابزار هرگز از کاتالوگ گرفته نمیشه.
- اگه کاتالوگ برای سروری اطلاعات نصب نداشته باشه، به درخواست تو از README اش
  خونده میشه؛ هر چیزی که اینطوری حدس زده بشه برچسب هشدار میگیره و قبل از ذخیره
  بازبینی میشه.

## مهارت های ایجنت

هر مهارت پوشه ای با فایل `SKILL.md` هست - frontmatter YAML
(`name` + `description`) به همراه بدنه مارکداون. اول فقط نام و توصیف
بارگذاری میشه؛ ایجنت وقتی درخواست تو جور شد، بقیه رو از طریق ابزار
`skill` میخونه. ترتیب جستجو (اولین تطابق برنده):

- `.xratu/skills/<name>/SKILL.md`
- `.agents/skills/<name>/SKILL.md` (مشترک با ابزار های ایجنتی دیگه)
- `.claude/skills/<name>/SKILL.md` (Claude Code)
- `~/.agents/skills/<name>/SKILL.md`
- `~/.claude/skills/<name>/SKILL.md` (Claude Code)

```markdown
---
name: deploy-staging
description: Deploy the app to staging; use when the user asks to deploy or ship to staging.
---

1. Run the test suite
2. Build the app
3. `npm run deploy:staging`
```

فایل های جانبی (اسکریپت، مرجع، قالب) کنار `SKILL.md` قرار میگیرن.
فعال/غیرفعالسازی مهارت ها توی Settings → Servers & skills → Skills.

### مهارت های اول

خراتو شش مهارت همراه خودش میاره، که موقع اولین اجرا توی `~/.agents/skills`
کاشته میشن (پس Claude Code، OpenCode و بقیه ابزار های ایجنتی هم میبینن)،
مثل هر مهارت دیگه ای قابل ویرایشن، و از Settings → Servers & skills →
Skills میشه تک به تک خاموششون کرد:

| مهارت | چه میکنه |
|-------|----------|
| `natural-farsi` | فارسی رو جوری مینویسه که توسعه دهنده های ایرانی واقعا تایپ میکنن - لهجه محاوره ای (رو، همون، میخوای) نه شکل کتابی، بدون نیم فاصله، و اصطلاحات فنی به انگلیسی. وقتی زبان پاسخ فارسی باشه خودکار بارگذاری میشه. |
| `finglish-normalize` | فینگلیش (فارسی با حروف لاتین) رو به عنوان فارسی میفهمه و زبان و خط جواب رو با تو هماهنگ میکنه. |
| `jalali-dates` | تاریخ های جلالی توی متن؛ تاریخ های ماشین خوان ISO میمونن. |
| `iran-dev-access` | از ایران چی کار میکنه و جایگزینش چیه - گیت وی های داخلی، مدل های محلی، PaaS ایرانی. |
| `iran-connectivity-fallback` | ارایه دهنده مدام timeout میده؟ جایگزین هایی رو پیشنهاد میده که از قبل روی سیستمت تنظیم شدن - بدون راهنمای دور زدن. |
| `local-llm-low-ram` | حساب و کتاب صادقانه سایز مدل برای اجرای محلی روی سیستم های کم حافظه. |

## زیرعامل ها

زیرعامل یه پروفایل ایجنت با اسم مشخصه که ایجنت اصلی میتونه یه کار
خودبسنده رو با ابزار `task` بهش بسپاره. زیرعامل یه حلقه ایجنت کامل رو توی
یه **زمینه تازه** اجرا میکنه؛ گفتگوی تو رو نمیبینه و در پایان فقط گزارش
نهاییش برمیگرده. نتیجهش اینه که یه جستجوی طولانی یا یه بررسی چند فایلی از
پنجره گفتگوی تو بیرون میمونه و ایجنت اصلی میتونه همزمان کار خودش رو
ادامه بده.

دوتا پروفایل به صورت پیش فرض وجود داره:

| پروفایل | کارش چیه |
|---------|----------|
| `explore` | پژوهش. فایل ها رو میخونه، جستجو میکنه و برای راستی آزمایی گزارشش **دستور های فقط خواندنی** اجرا میکنه (build، type-check، تست، linter، `git log`). هیچ ابزار ویرایشی نداره، پس نمیتونه چیزی رو تغییر بده. |
| `general` | کار چند مرحله ای: بررسی، ویرایش، اجرای دستور و راستی آزمایی. |

وقتی مدل توی یک پیام چند تا واگذاری میخواد، همزمان اجرا میشن. تنظیم
`xratu.maxParallelSubagents` (پیش فرض ۴) سقف همزمانی رو میذاره، چون هر
کدوم یه حلقه ایجنت کامل با زمینه و بودجه خودشه. رد کردن از این سقف خطا
نیست؛ بقیه به همون ترتیب و با خالی شدن جا اجرا میشن.

### نوشتن فایل زیرعامل

از پالت فرمان **Xratu: Agent Files** همه پروفایل هایی که خراتو بارگذاری
کرده رو میبینی، از جمله اون هایی که خراب شدن و دلیلش رو هم میبینی، و
میتونی یکی جدید بسازی. فایل ها مارکداون ساده با frontmatter YAML هستن و
بدنه فایل، پرامپت سیستم زیرعامل میشه. ترتیب جستجو (اولین تطابق برنده):

- `.xratu/agents/<name>.md`
- `.agents/agents/<name>.md` (مشترک با ابزار های ایجنتی دیگه)
- `.claude/agents/<name>.md` (Claude Code)
- `~/.agents/agents/<name>.md`
- `~/.claude/agents/<name>.md` (Claude Code)

```markdown
---
name: code-reviewer
description: کد تغییر کرده رو از نظر درستی و امنیت بررسی میکنه؛ بعد از یه ویرایش بزرگ استفاده میشه.
tools: read_file, grep_search, glob_search, run_terminal_command
model: gpt-5-mini
reasoning_effort: low
max_rounds: 30
---

دیف کد رو از نظر مشکلات درستی و امنیت بررسی کن. هر یافته رو با مسیر فایل
و شماره خط بده، از مهم ترینشون شروع کن.
```

| فیلد | معنی |
|------|------|
| `name` | اختیاری؛ باید با اسم فایل یکی باشه (حروف کوچک، عدد و خط تیره تکی). |
| `description` | **اجباری.** کی باید کار به این زیرعامل واگذار بشه؛ مدل از روی همین خط پروفایل ها رو انتخاب میکنه. |
| `tools` | لیست اختیاری اسم ابزارها. اگه ننویسی، همه ابزارها به جز `task` و `ask_user_question` رو میگیره که هیچ زیرعاملی اون دو رو نداره. |
| `model` | اختیاری. این پروفایل رو روی یه مدل مشخص اجرا کن (پنجره زمینه و سقف خروجی هم از همون مدل گرفته میشه). پیش فرض: مدل همین گفتگو. |
| `reasoning_effort` | اختیاری: `none`، `minimal`، `low`، `medium`، `high`، `xhigh`، `max`. |
| `max_rounds` | بودجه حلقه این پروفایل (پیش فرض ۵۰). |

اسم های `tools:` موقع بارگذاری فایل با ابزارهایی که نصب تو واقعا داره
بررسی میشن. اسم هایی که وجود ندارن حذف میشن و یه هشدار میگیری، و لیستی که
**هیچ** اسم معتبری توش نباشه خطای جدیه، نه یه زیرعاملی که بی سروصدا هیچ
کاری نمیتونه بکنه. این نکته مهمه چون فایل هایی که برای ابزارهای دیگه
نوشته شدن اسم ها رو به شکل `Read`، `Grep`، `Bash` مینویسن. برای دیدن این
ها **Xratu: Agent Files** رو باز کن یا توی خروجی **Xratu** نگاه کن.

زیرعامل زمینه خودش رو داره، نمیتونه خودش واگذاری کنه، وسط کار نمیتونه ازت
سوال بپرسه، و ویرایش ها و دستورهاش هم مثل دستورهای خودت از همون تایید
رد میشن. نتیجه هر اجرا با یه `task_id` برمیگرده: همون id رو توی یه فراخوانی
بعدی `task` بفرست تا همون زیرعامل با زمینه قبلیش ادامه بده، به جای اینکه کار
رو از اول شروع کنه. عمر یه `task_id` تا وقتیه که همون گفتگو توی همون پنجره
VS Code باز باشه؛ ری استارت کردن پنجره کار رو تموم میکنه.

## پروکسی

صفحه Settings → Proxy مسیر ترافیک خروجی رو کنترل میکنه:

- **حالت ها** - خودکار (تنظیم Xratu، بعد VS Code، بعد متغیر های محیطی، بعد
  پروکسی سیستم عامل)، سفارشی (یه آدرس پروکسی مشخص به همراه لیست no-proxy)
  یا خاموش.
- **اسکن کلاینت محلی** - کلاینت های خانواده Clash (Clash Verge Rev، mihomo،
  Mihomo Party، Clash Nyanpasu، ClashX)، v2rayN/v2rayA یا Surge رو که روی
  سیستمت هست پیدا میکنه و به پورت هاشون قفل میشه. حالت System Proxy کافیه -
  بدون TUN.
- **مسیریابی هر سرور MCP** - هر سرور MCP میتونه خودکار / از طریق پروکسی /
  مستقیم بره، با یه تست اتصال زنده قبل از ثبت.
- کاتالوگ های فروشگاه MCP سمت افزونه و از همین پروکسی گرفته و ۲۴ ساعت کش
  میشن.

## حریم خصوصی

کلید های API توی مخزن secrets ادیتور VS Code نگه داشته میشن و فقط به
اندپوینتی که خودت تنظیم کردی ارسال میشن. تاریخچه گفتگو و Checkpoint ها
فقط روی دیسک تو هستن.

دو تا از قابلیت ها عمدا از سیستم تو بیرون میرن:

- **جستجوی وب** کوئری رو میفرسته برای همون سرویسی که تنظیم کردی - SearXNG
  خودت (`xratu.webSearchUrl`)، وگرنه Brave Search؛ Parallel هم قابل انتخابه.
- **Fetch URL** صفحه ای که تو یا ایجنت نام میبره رو درخواست میکنه، بعد از
  اینکه گارد SSRF آدرس های خصوصی و لوپ بک رو رد کنه.

سرور های MCP، مهارت ها و فایل های ایجنت از دیسک تو خوندن میشن. هیچ تله
متریسی وجود نداره؛ نه آنالیتیکسی هست نه گزارش کرش. مشکل امنیتی رو از
[SECURITY.md](SECURITY.md) گزارش کن، نه از Issue عمومی.

### راه اندازی محلی و مقایسه اتصال ها

توی تنظیمات، حالت آفلاین و گزینه توضیح خطا ها اضافه شده. حالت آفلاین درخواست های HTTP خود خراتو رو به همین سیستم محدود میکنه، ابزارهای وب و MCP خارجی رو میبنده و عملیات فعال رو لغو میکنه. دستورهای ترمینال محدود نمیشن. نوار ثابت بالای صفحه به [راهنمای آفلاین و سخت افزار](assets/guides/offline.fa.md) وصل میشه؛ این راهنما توی بسته نصب هم هست و از صفحه سرویس دهنده ها هم باز میشه.

برای یه رانتایم Ollama شناسایی شده روی پورت `11434`، بخش مدیریت مدل ها رو توی صفحه سرویس دهنده ها باز کن. دانلود پیشرفت و دکمه لغو داره؛ حذف تایید لازم داره. مدل های رانتایم های دیگه رو توی خود برنامه مدیریت کن. راهنما انتخاب اندازه مدل، مقدار RAM و VRAM، کوانتایز و رفع مشکل آفلاین رو توضیح میده.

گزینه های ایرانی به صفحه رسمی شروع کار وصل میشن. [راهنمای مقایسه ارائه دهنده ها](assets/guides/providers.fa.md) اطلاعات قیمت و پرداخت تایید شده رو از تعرفه های تایید نشده جدا میکنه. تست سرعت یه درخواست کوتاه و اختیاری به مدل فعال میفرسته و زمان اولین token متنی، زمان کل و قیمت و هزینه تخمینی موجود رو نشون میده. محتوای پروژه فرستاده نمیشه؛ درخواست ممکنه هزینه داشته باشه. برای مقایسه همون مدل رو انتخاب کن و چند بار اندازه بگیر.

تست تصویری فروشگاه توی CI لینوکس برای فارسی و انگلیسی، عرض های ۴۲۰ و ۹۰۰ پیکسل و حالت های فهرست، تایید و آفلاین اجرا میشه. فونت همراه برنامه و نسخه ثابت Chromium استفاده میشن؛ چک های چیدمان روی ویندوز و مک هم اجرا میشن.
