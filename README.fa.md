## شروع به کار

[خراتو رو از فروشگاه `VS Code` نصب کن](https://marketplace.visualstudio.com/items?itemName=xratu.xratu).
برای نصب دستی، فایل `.vsix` رو از [نسخه ها](https://github.com/thesamehosuh/xratu/releases)
بگیر و توی `VS Code` گزینه **`Extensions → ⋯ → Install from VSIX…`** رو بزن.

۱. پوشه پروژه رو توی `VS Code` باز کن، بعد خراتو رو از نوار کناری باز کن.
۲. یکی از مسیرهای **شروع رایگان**، **سرویس خودم** یا **اجرای محلی** رو انتخاب کن.
۳. یه مدل انتخاب کن، **شروع گفتگو** رو بزن و بگو چی میخوای بسازی یا درست کنی.

| مسیر | چی لازم داری |
|------|--------------|
| **شروع رایگان** | خراتو میتونه `OpenCode` 2 رو نصب کنه. در دسترس بودن مدل های رایگان و محدودیت درخواست به `OpenCode` بستگی داره. |
| **سرویس خودم** | به سرویس خودت وصل شو؛ سرویس های ایرانی و اندپوینت دلخواه سازگار با `OpenAI` هم پشتیبانی میشن. |
| **اجرای محلی** | `Ollama`، `LM Studio`، `vLLM` یا `llama.cpp` رو با یه مدل آماده اجرا کن. |

برای تغییر اتصال، **تنظیمات ← ارائه دهنده ها** رو باز کن. برای انتخاب موتور
گفتگوی تازه، به **تنظیمات ← موتورهای اجرا** برو.

## چه کارهایی میتونی بکنی

- از ایجنت بخواه کد رو بخونه، فایل ها رو ویرایش کنه، دستور اجرا کنه و دنبال مشکل بگرده.
- با **حالت برنامه ریزی** بررسی و برنامه ریزی کن؛ تغییرات توی این حالت مسدودن.
- عکس، PDF یا کد پیوست کن و وسط کار مسیر ایجنت رو عوض کن.
- تفاوت فایل ها رو توی **تغییرات**، خروجی کامل رو توی **فعالیت** و دستورهای
  در حال اجرا رو توی **پس زمینه** ببین. هر وقت لازم شد، فایل ها رو از چک پوینت برگردون.
- با ایجنت توی **مرورگر** مشترک کار کن یا با **MCP**، **مهارت ها** و **ایجنت ها**
  ابزار و روش کار دلخواهت رو اضافه کن.

موتور خود `Xratu` از مدل محلی، زیرعامل ها و برگردوندن گفتگو پشتیبانی میکنه.
`OpenCode` از اتصال ها و نشست های خودش استفاده میکنه؛ زیرعامل ها، برگردوندن
گفتگو و حالت آفلاین فعلا توی این موتور در دسترس نیستن.

## پیگیری درخواست های ادغام

ایجنت PR هایی رو که میسازه یا روشون کار میکنه به گفتگو وصل میکنه. وضعیت PR
کنار کادر پیام و توی فعالیت نشون داده میشه؛ نتیجه بررسی ها و نشونه پیگیری
هم همون جاست. با انتخابش، جزئیات توی پنل کناری **درخواست ادغام** باز میشه.
این تب فقط وقتی PR به گفتگو وصل شده باشه دیده میشه. اول GitHub CLI رو نصب کن و
`gh auth login` رو اجرا کن. فعلا فقط github.com پشتیبانی میشه؛ اتصال API
گیت هاب و روش ورود برای `git push` جدا هستن.

**شروع پیگیری** هر دو دقیقه، وقتی میزبان افزونه VS Code بازه، خطای بررسی ها،
موفق شدن بررسی های لازم، نظرهای جدید و تداخل branch رو چک میکنه. لینک ها،
وضعیت پیگیری و خبرهای بررسی نشده بعد از بارگذاری دوباره میمونن. حالت آفلاین
و بستن VS Code پیگیری رو مکث میدن. محدودیت درخواست GitHub هم فقط باعث مکث
میشه. نظرهای همون حساب خودت خبر جدید حساب نمیشن تا حلقه پاسخ ایجاد نشه.

از ایجنت بخواه PR رو پیگیری کنه تا خبرهای جدید رو توی همون گفتگو بررسی کنه.
از جزئیات PR هم میتونی پیگیری رو شروع یا متوقف کنی. این کار از سهمیه مدل استفاده میکنه و
تایید ابزارها همچنان لازمه. اگه گفتگو فعال نباشه، اجرا مشغول باشه یا branch،
مدل، حساب یا موتور عوض شده باشه، خبرها توی پنل PR منتظر میمونن. فهرست گفتگوها
هم تعداد خبرهای جدید رو نشون میده. ادامه ای که قطع شده باشه، بدون اقدام دوباره
تو اجرا نمیشه. **توقف پیگیری**، **حذف لینک** و دکمه توقف گفتگو، ادامه های
منتظر رو لغو میکنن. بسته شدن یا merge شدن PR، هشت خطای دریافت یا ده خبر
متوالی فقط درباره نظرها هم پیگیری رو تموم میکنن.

ابزارهای `link_pull_request`، `unlink_pull_request`، `list_thread_pull_requests`،
`get_pull_request`، `watch_pull_request` و `unwatch_pull_request` توی هر دو موتور
در دسترسن. ایجنت PR هایی رو که میسازه با ابزار لینک به گفتگو وصل میکنه.
زیرعامل ها میتونن وضعیت رو بخونن، ولی تغییر لینک یا پیگیری فقط دست گفتگوی
والده. این ابزارها خودشون چیزی رو merge یا منتشر نمیکنن.

توی `git_commit`، گزینه `files` فقط محتوای فعلی مسیرهای انتخاب شده رو commit
میکنه و مرحله بندی فایل های دیگه رو نگه میداره. بدون `files` یا `stage_all`،
همون تغییرات از قبل مرحله بندی شده commit میشن. خطای مرحله بندی کار رو متوقف میکنه.

## تایید کارها و حریم خصوصی

ویرایش ها، دستورها و کار با ابزارها کنترل تایید دارن. **حالت YOLO این
درخواست های تایید رو حذف میکنه**؛ فقط وقتی روشنش کن که بخوای ابزارها بدون
تاییدت کار کنن. چک پوینت ها توی فضای جداگانه گیت ذخیره میشن و تاریخچه و
مرحله بندی گیت پروژه رو دست نمیزنن.

کلیدهای API توی مخزن امن `VS Code` نگه داشته میشن. تاریخچه گفتگو و چک پوینت ها
روی سیستم خودت میمونن. درخواست ها و محتوای مرتبط برای سرویس انتخابی فرستاده
میشن؛ ابزارهای وب و سرورهای MCP هم به سرویس تنظیم شده وصل میشن. افزونه
داده آماری جمع نمیکنه. برای کار محلی، یه مدل محلی انتخاب کن و **حالت آفلاین**
رو روشن کن؛ دستورهای ترمینال همچنان محدود نمیشن.
